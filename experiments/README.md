# Проверка гипотез — 22 сентября 2026

Сравниваем с текущей стратегией `improved`: 512 выборочных расстановок, выбор по вероятности и точная концовка. Набор кораблей и запрет соприкосновения одинаковы во всех вариантах. Алгоритмы получают только наблюдаемое поле; результаты каждого выстрела определяет отдельный симулятор.

## Протокол до выбора победителя

1. Разведочная серия: 200 одинаковых полей, seed `482159`. Кандидаты: доля детерминированной карты 25%, 50%, 75%; отдельно бонус 0,25 за энтропию ответа на выстрел. Выбираем кандидата с наименьшим средним числом выстрелов.
2. Проверка выбранного кандидата на новых данных: 600 полей, seed `731059`. Настройки после разведочной серии не меняем. Выигрыш считаем подтверждённым для случайного генератора, если верхняя граница приблизительного парного 95%-го доверительного интервала разницы числа выстрелов ниже нуля. Отрицательная разница означает меньше выстрелов у кандидата.
3. Проверка устойчивости: 200 полей, seed `904213`, многопалубные корабли преимущественно по краям. Если обнаруживается убедительное ухудшение (нижняя граница парного 95%-го интервала выше нуля), кандидат не включается по умолчанию как универсальное улучшение.
4. Непрошедшие проверку варианты остаются явно включаемыми экспериментами. Основная стратегия автоматически не переключается.

## Гипотезы

`blend0.25`, `blend0.5`, `blend0.75`: в фазе поиска смешиваем выборочную вероятность с числом допустимых положений отдельных кораблей. Детерминированную карту нормируем так, чтобы её сумма равнялась числу оставшихся непоражённых палуб. Полученная величина служит только для ранжирования; показанный шанс попадания остаётся исходной выборочной вероятностью. Добивание и точная концовка не меняются.

Идея смешения описана разработчиком [SONAR](https://github.com/wilkolbrzym-coder/SONAR). Здесь проверяется собственная реализация с фиксированными весами, а не воспроизведение его заявленных результатов.

`information0.25`: в фазе поиска к вероятности попадания добавляем 0,25 × энтропию трёх наблюдаемых исходов: промах, попадание без потопления, потопление одиночки. Это самостоятельная проверяемая адаптация идеи ценности информации из [разбора Patrick O’Neill](https://www.nulliq.dev/posts/battleship/), а не реализация описанного там подсчёта исключаемых положений кораблей. Без открытых попаданий сразу потопить многопалубный корабль невозможно.

## Запуск

```sh
POLICIES=improved,blend0.25,blend0.5,blend0.75,information0.25 node benchmark.js 200 512 482159
# После фиксации кандидата, например blend0.5:
POLICIES=improved,blend0.5 node benchmark.js 600 512 731059
PLACEMENT=edges POLICIES=improved,blend0.5 node benchmark.js 200 512 904213
```

Исходные результаты сохраняются в JSONL. Разведочные данные не объединяются с проверочными для заявления о выигрыше. Генератор случайных полей последовательно размещает корабли; он не даёт равномерной выборки всех возможных флотов и не описывает привычки человека. Конечная выборка вероятностей и ограничения времени также могут влиять на результат.

## Выбор кандидата

Разведочная серия завершена: `improved` — 55,310; `blend0.25` — 55,025; `blend0.5` — 54,555; `blend0.75` — 54,740; `information0.25` — 56,005. Для независимой проверки зафиксирован **`blend0.5`**. Его преимущество в разведочной серии составляет 0,755 выстрела, но 95%-й интервал разницы [−1,902; +0,392] включает ноль. Это основание для дальнейшей проверки, а не для включения по умолчанию.

Эталонные прогоны проверочных серий запущены заранее отдельно от кандидата; их результаты не использовались при выборе веса. Для обеих стратегий используются одинаковые seed полей и одинаковые потоки случайных чисел для выбора среди равноценных ходов.

## Проверочные результаты и решение

| Серия | Полей | Текущая стратегия | Смесь 50/50 | Разница | Парный 95%-й интервал |
|---|---:|---:|---:|---:|---:|
| Новые случайные поля | 600 | 55,165 | 54,983 | −0,182 | [−0,874; +0,510] |
| Многопалубные корабли у краёв | 200 | 57,600 | 59,300 | +1,700 | [+0,392; +3,008] |

**По умолчанию смесь не включена.** Первоначальный выигрыш не подтвердился на независимой случайной выборке, а при размещении кораблей у краёв обнаружено ухудшение. Бонус за информацию проиграл на разведочной серии и не был выбран для проверки. Это результат конкретных вариантов и генераторов, а не доказательство невозможности улучшить алгоритм.

Всего выполнено 2600 полных партий: 200 полей × 5 стратегий для выбора кандидата, 600 × 2 для проверки, 200 × 2 для проверки краёв. В каждой серии — 512 расстановок на ход; незавершённых общих расчётов не было. Использован Node.js 22.14.0. Точные концовки, добивание и исходная оценка вероятностей одинаковы между вариантами.

### Файлы и повторный анализ

- `discovery.jsonl` — разведочная серия.
- `validation.jsonl` — парное сравнение на новых случайных полях.
- `edges.jsonl` — парное сравнение на полях с приоритетом краёв.
- `*-reference.jsonl`, `*-candidate.jsonl` — исходные раздельные прогоны, включая время и число точных решений.

```sh
python3 experiments/merge.py experiments/validation-reference.jsonl experiments/validation-candidate.jsonl experiments/validation.jsonl
python3 experiments/merge.py experiments/edges-reference.jsonl experiments/edges-candidate.jsonl experiments/edges.jsonl
python3 experiments/summarize.py experiments/discovery.jsonl experiments/validation.jsonl experiments/edges.jsonl
```

Эксперименты доступны через `analyze(board, { huntBlend: 0.5 })` или `analyze(board, { informationWeight: 0.25 })`. Оба веса по умолчанию равны нулю; интерфейс их не включает. В профиле `edges` выбираются допустимые положения многопалубных кораблей целиком на границе, когда такие положения есть; иначе используется обычное допустимое размещение. Одиночки ставятся случайно.
